
# ROS2 轮腿控制器大作业

## 1. 控制结构 (Architecture)
本项目将原单进程拆分为两个独立 ROS2 节点，通过话题通信，控制器内无 `mujoco` 依赖。

**核心控制流：**
1. **输入回调**：`imu_cb` 接收姿态角，`joint_cb` 接收关节数据并触发 `step()` 解算，`cmd_cb` 接收速度指令。
2. **状态处理**：加入 `joints_ready` 标志位，保证 6 个关节数据到齐后才发指令，防异步崩溃。
3. **核心解算 (`step`)**：
   - 用 `VelocityRampFilter` 平滑目标速度。
   - 更新 `x_b_set`（仅运动中更新，防止站桩滑走）。
   - 左右腿分别调用 LQR 状态反馈 + VMC 运动学 + 腿长 PID。
4. **下发**：打包 6 个力矩发布到 `/actuator_cmd`。

```text
[输入层]               [控制层]                      [输出层]
/imu ───────> imu_cb() ─┐
                        │
/joint_states ─> joint_cb() ──> step() ──> 打包 6 个关节力矩 ──> /actuator_cmd
                        │         │
/cmd_vel ────> cmd_cb() ┘         └─(LQR状态反馈 + VMC正运动学 + 腿长PID)
```

## 2. 参数来源与工程优化
- **K 矩阵来源**：复用原版 `lqr_update.py`，未盲目乱调。
- **启动防崩**：加入了 `joints_ready`，彻底解决了第一帧数据不全导致的节点崩溃。

## 3. 实测数据与验收结果

- **原地平衡**：
  - **平衡时长**：> 30 秒（无外力干扰下持续稳定）。
  - **Pitch 偏差**：稳态下俯仰角极稳，实测终端日志显示 Pitch 波动在 **±0.2°** 以内。
  
- **速度跟踪（阶段 5 加分项）**：
  - 发送 `/cmd_vel linear.x = 0.3` 目标速度后，平稳向前行驶超 3 米不摔倒。速度爬坡滤波器工作正常。
  
- **抗扰与保护**：
  - 在 MuJoCo 窗口施加外力推搡，机器人能恢复直立。
  - 调试阶段已解决“五连杆双解导致的腿部异常折叠”问题，并加入了关节限幅保护。

## 记录

1. **算法复用**：直接调用的原版 `lqr_update.py` 和 `vmc_cal.py`。
2. **AI 帮忙的部分**：借助 AI 写了 ROS2 节点的基本框架（比如回調函數），把 `/imu`、`/joint_states`、`/cmd_vel` 的订阅和 `/actuator_cmd` 的发布打通了。
3. **实际跑通过程（调试记录）**：
   - **启动直接崩溃**：原版是单进程，随时读都有数据；拆成 ROS2 后，第一帧数据不全，直接报 `KeyError` 节点退出了。后来加了个 `joints_ready` 判断，等 6 个关节数据全到齐再开始算。
   - **小车腿部無法復原**：詢問学长，得知 五连杆算法有“双解”，特定角度下会算出相反的构型。后来直接在代码里给解算出来的 `L_0` 和 `theta` 加了物理限幅（比如限制在 0.05~0.25 之间），强行规定了几何解。
4. **测试结果**：算法和参数完全使用原版，没有调参（除了加限幅）。能原地平衡，发 `/cmd_vel` 也能平稳前进，没有出现抽搐。
